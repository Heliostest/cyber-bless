# 八语言 i18n 与排版设计

日期：2026-10-27。状态：用户已批准直接实施。事实依据与基线结果见 [审计报告](../../research/2026-10-27-i18n-layout-audit.md)；实际交付与验证边界见 [验收记录](../../research/2026-10-27-i18n-acceptance.md)。本设计中的验证要求与实际已执行结果分别记录，不能把设计目标当作通过证据。

## 目标与完成定义

让 Web、Expo DOM、Native 宿主和 iOS/Android 小组件一致支持简体中文、繁体中文、英文、日语、韩语、西班牙语、葡萄牙语、法语。翻译、输入、排版、持久化、错误恢复与离线体验均需覆盖，不能仅增加一个语言选择器。

“完整”的交付条件是：八语言发布词表通过覆盖/ICU/参数/陈旧译文校验；所有实际用户入口有译文；语言切换不丢进度和草稿；小屏、长译文及放大文字不遮挡操作；原生组件和旧存档通过验证。技术验证、语言审校、文化核查、真机检查分别报告，未完成项不写成“完美”。

当前已有 154 个场景（87 个公开可见）；本轮覆盖全部随包且实际可达的场景文案、介绍与旧记录展示。研究仓库的 1,600 份来源 Markdown 不整体翻译；实际展示的来源说明、页面内法律/支持文本仍需翻译。

不增加账号、在线翻译服务、付费功能或新仪式。场景技术 ID、引擎版本、日历选择和奖励规则沿用原契约。商店材料可在本地准备八语言版本，上传、提审与发版另按用户授权执行。

## 方案比较与建议

| 路线 | 优点 | 代价与适配 |
| --- | --- | --- |
| FormatJS：@formatjs/intl + react-intl | 一个 ICU 消息语法，纯 JS 与 React 共用格式化、抽取与编译 | 增加工具链；原生 widget 仍要从同源词表生成精简资源 |
| i18next + react-i18next + i18next-icu | 成熟 React 生态，命名空间与异步后端选择丰富，同样支持非 React | ICU 需要额外插件；本项目离线内置内容暂不需要大量后端编排 |
| 自制字典/字符串替换 | 起步依赖少 | 复数、参数、工具与审核机制需自行重做，不适合作为长期方案 |

建议采用第一条。此选择及以下默认值为本方案的工程判断，待用户整体确认；未将其记成用户已批准。优先复用现有 React/Vite/Expo 架构。

## 语言、匹配与偏好

规范 ID：`zh-Hans | zh-Hant | en | ja | ko | es | pt | fr`。设置提供“跟随系统”和每种语言的自称：简体中文、繁體中文、English、日本語、한국어、Español、Português、Français。

- 单独定义 `LocalePreference = 'system' | SupportedLocale`，用类型明确的 action 更新；旧存档没有该字段时为 system，错误值回到 system。
- 按系统首选语言列表依次匹配，不因第一项不支持便提前回退。显式中文 script 优先：zh-Hant、zh-Hans；无 script 时 zh-TW/HK/MO→Hant，其余 zh→Hans。
- en-GB/en-US→en，es-MX/es-ES→es，pt-BR/pt-PT→pt，其余目标语言类似。葡语词表采用中性表达；本轮不另分巴西和欧洲葡语词表。
- 拆分 `messageLocale` 与 `formatLocale`：系统匹配时保留选中地区标签用于日期/数字；手动语言使用该语言标签，未来可独立增加地区偏好。时区与 12/24 小时系统偏好单独处理。
- 全部首选语言都不支持时，建议回退 en。defaultLocale 仍为源文案 zh-Hans；这是消息语法的源语言，不等同系统不支持时的 UI 默认值。
- RN 通过 expo-localization 的 SDK57 版本取得首选语言，传给 DOM；Web 读取 navigator.languages，监听 languagechange；Native 回到前台重读，手选语言不被覆盖。
- 偏好保存在主存档 `settings.locale`，启动宿主在已有的一次存档读取中提前提取并校验偏好，连同初始语言交给 DOM。失败页由宿主先用该偏好或系统语言渲染，避免首屏中文闪烁。不得为取偏好在宿主写回或覆盖损坏存档。
- 运行时单一 language controller 发布 resolved locale。Web 多标签更新遵循现有存储冲突规则；不得为同步语言整份覆盖较新的心愿记录。

## 包与 API 边界

新增纯 JS workspace `packages/i18n`，不依赖 DOM、React、RN 或业务状态。包含语言注册表、匹配器、消息 ID/参数类型、ICU 目录、formatter 工厂与小组件资源生成输入。React Provider 放在 `packages/app`；Native 可在 DOM 崩溃时直接使用小词表。

建议资源结构：

```text
packages/i18n/src/
  locales.ts                  # 注册、解析与地区匹配
  messages.ts                 # 稳定语义 ID 与参数契约
  format.ts                   # createIntl/cache；日期、数字、列表
  catalogs/<locale>/
    app.json                  # 页面、错误、ARIA、公共手势
    scenes.json               # 154 个场景的短文案
    narratives.json           # 介绍
    legal.json                # App 内法律和支持文本
  review-manifest.json        # 源消息 hash、译文状态与审阅记录
```

八种语言资源全部随安装包/站点产物发布；长介绍可按语言/场景分块，但首次离线启动时必须在 Expo 嵌入产物中可用，不能依赖 CDN 后才算支持。Native 启动和 widget 不加载全部长介绍。验收记录新增 JS/压缩包/字体体积和启动时间；既有大 chunk 警告不因加词表进一步失控。

消息使用 `wish.notes.count`、`scene.omikuji.instruction.read` 等稳定 ID，参数有类型。句子以整句翻译；数量用 ICU plural/select，日期、时间、数字、列表用 Intl。禁止翻译后再拼接中文单位或按字符串内容判断错误类别。

提取覆盖 JSX、ARIA、title、placeholder、DOM textContent、Canvas 默认文字、提示、错误与系统事件。元数据、注册表、模块及宿主展示通过同一 scene ID 查译名；不复制八套场景身份。

## 场景、远端内容与动态切换

- 给 SceneContext/旧 procedural adapter 注入 locale-aware formatter 与订阅接口；formatter 使用当前 locale，场景订阅后刷新文字节点、提示、ARIA 和 Canvas 默认文字，dispose 时取消订阅。
- 禁止简单以 locale 为 React key 销毁引擎。切换时保留整数/细分 checkpoint、variant、在写草稿、焦点和滚动；活跃手势可按现有暂停协议安全取消，不重置已提交进度。
- Canvas 用实际字体的 measureText 和词/字素边界换行；字体就绪、容器/语言变化时重绘。纸面空间不足时保留完整原文的 DOM 阅读入口，不静默丢掉后半句。
- 内置审核过的 ID 优先使用本地译文；远端同 ID 的 title 不得覆盖审核译名。旧目录仍可解析单语言 title。
- 新远端文本可增加有界、白名单语言映射及 sourceLocale，schema 显式版本化；保持 hash 校验和 URL 规则。完整支持本轮内置内容不依赖远端协议立刻升级。
- 未知远端条目没有目标译文时，按 target→en→sourceLocale 显示原始已校验文字，并标注实际 lang；不假装已翻译。该情况是第三方/新内容的降级边界，不允许用它掩盖内置八语言词表缺失。
- 文字修订版本与 engine 交互版本分开；不得仅为译文改引擎版本、改变文化来源 slug 或隐藏/展示清单。

## 存档、用户输入与错误

- 继续读取 v1 存档和原 key。已知收藏/场景按 kind、sceneId 显示当前译名，旧 title 作为未知内容保底；不将翻译写回覆盖原始历史标题。
- 新系统笔记存结构化事件类型及参数，显示时翻译；用户笔记、心愿和留言永远保持原文。旧系统笔记只在机器 ID、关联数据与精确已知格式共同证明身份时适配，否则保留原文，避免误改用户输入。
- core/runtime 返回稳定错误 code 和参数；App/Native 显示本地化恢复动作。诊断 detail 继续供日志使用，不直接展示 URL/英文异常，也不以“含汉字”判断安全提示。
- 字数统一为用户感知字素；使用 Intl.Segmenter 并检测目标 WebView/Hermes 能力，按需引入必要替代。输入上限、按钮校验、服务/核心校验同源，另设足够宽的编码大小安全限额。
- IME composition 期间不截断、不误提交；emoji、组合重音、日/韩输入可往返保存。旧记录不因新长度单位而被删除；存档恢复测试包含旧边界和超出新输入限制的保留数据。
- 日期展示可以变，ISO timestamp、yyyy-MM-dd 协议、localDay、推荐种子、时区/DST 算法不能随 UI 语言变化。价格若以后引入，必须保留商店返回的本地价格，不能自行换汇。

## 排版规则

1. **标题与按钮：** 取消字符数除宽度的字号算法。常规标题可换行，装饰 ribbon 随高度扩展；沉浸标题优先两行，空间不足时给完整可访问阅读入口，文字基准尺寸保持可读。按钮、筛选项、设置行用自动高度和足够点击区域，长译文允许堆叠。
2. **字体：** 用 :lang 为 Hans/Hant/ja/ko 和 Latin 选择正确本地字形。优先使用系统可用字体；所需离线补充字体随包携带，并记录授权、字形覆盖和体积。Latin 必须覆盖西/葡/法语及组合重音，不限于 U+00FF。字体失败测试仍须可读。
3. **断行：** 中文/日文按对应语言断行，韩文优先词边界；拉丁正文 normal/auto hyphenation（支持时）及合理兜底。overflow-wrap:anywhere 只用于长 URL/不可断用户串等必要场景；不全局 break-all，不在英文字符间加中文式字距。
4. **布局：** Flex/Grid 子项设置 min-inline-size:0、minmax(0,1fr)，使用逻辑方向属性；计数、装饰、图标不挤占正文。底部导航保留短译名、完整 ARIA 和至少 44px 点击区域，允许两行并据实分配内容安全区。
5. **沉浸场景：** 用测量到的 header/footer/overlay 高度计算舞台范围；长提示、介绍和完成按钮不与 canvas 操作区重叠。舞台保留最小可操作尺寸，短屏或大字时改为可滚动回流布局。介绍面板宽度必须不超过实际可用空间；取消以 nowrap 按钮宽度作为面板最小宽度，测量多行按钮高度，替换固定 48px header/body offset。实测草稿大字时曾出现 464px 面板塞进 294px 区域，不能只检测 document 横向滚动。
6. **输入与可访问性：** 输入字号至少 16px；textarea 在值、宽度、语言和字体变化后自适应。document.lang、局部原文 lang、ARIA、live region、页面标题同步，切语言不抢焦点。支持文字放大、页面缩放、键盘/VoiceOver/TalkBack。

可见操作标签全部来自 DOM 词表，移除 CSS content 绘制的中文“辅助”。底部导航预留由实测 dock 高度驱动。现有三列器物架在窄屏/大字下允许变两列；拉丁译名优先按词换行。

这些规则是语言适配，保持现有美术方向。具体高度和断点由浏览器测量确定，不能再按四字中文估算。

## 原生宿主与小组件

Native 首屏、DOM 失败/重试、安全回退、App 名称和 widget gallery 文案都来自同源小词表。配置 iOS 主 App/extension 的 localizations、Android 语言资源与 locale config；技术包名、scheme 与 deep link 不变。

**协议选择：** 推荐新的公开 WidgetSnapshot v2 继续只携带 sceneId、day、category、artKey、collected、deepLink 等白名单数据，增加经过校验的 localePreference 与文案目录版本；显示标题在本地生成目录按 ID 解析。这样标题不再承担身份校验职责，但 ID、日期、URL、图键、目录版本与推荐一致性必须继续严格验证。读取旧 v1 时按原规则验证和转换，主存档 v1 不升级。

同一生成器从审核过的短词表生成 JS widget 常量、Swift/Android 目录、占位/失败文案、无障碍文本及 gallery 资源。构建检查生成物没有漂移；不向小组件传心愿、留言或私人标题。更新 widget-sync 的签名，纳入语言偏好、resolved locale 与词表修订；切语言和前台恢复触发重建 timeline。

Android 加 LOCALE_CHANGED 刷新，并以手选偏好或当前系统首选语言本地解析；time/timezone/boot 等既有刷新保留。所有尺寸和配置页均覆盖。

iOS SDK57 的序列化 widget 函数不能普通 import，WidgetEnvironment 也没有 locale。实现必须加入项目现有 config plugin 管理的、生成式原生 localization adapter：每次 extension render 取得原生首选语言/手选偏好，将有效语言注入独立 renderer；renderer 内嵌同源生成的小词表。资源实际加入 extension target。此适配不得直接手改 node_modules，plugin 在不匹配受支持 SDK57 模板时须明确构建失败。

优先在原生组件中读取系统语言并本地格式化，App 不运行时也不依赖 RN 重新发布字符串。系统决定 widget 何时重绘，不能承诺后台即时刷新；验收要求下次系统重绘/刷新使用新语言，且手选语言保持固定。如果受当前 Expo 模板限制无法可靠实现该 adapter，应把该项作为明确阻断项报告，不能悄悄降级成“打开 App 后才换语言”。

## 翻译与文化质量

- zh-Hans 为源语言；Hant 是独立词表，转换可辅助起草，但地道用词、标点及器物名需审校。其它语言保持温和、明确的产品语气。
- 维护术语表，重点包括许愿、还愿、祈福、收藏、仪式与器物原名。“还愿”不能简单当成 wish fulfilled；产品状态和真实传统语境分别写清。
- 每个场景译文关联原场景 ID、来源卡/研究记录、原文 hash、翻译及复核状态。译文不能新增效果保证、起源、固定数量、礼序或节期，也不能把真实宗教/信仰背景改成普通装饰。
- 纯忠实翻译可引用已有已核查事实；发生意义变化时重核受影响主张，按 scene-provenance 同步来源卡、研究记录、README、宿主、注册表、metadata 及原生标题。保留传统事实与产品动作的区分。
- 器物上固有书法、符号和传统对象名称可保留，另外翻译解释/读音；用户文字和历史原文属于原文内容，不以“残留中文”自动替换。
- 新增/修改消息使已翻译 source hash 过期，发布校验失败直到复核。自动扫描只查覆盖与疑点，不能声称母语或文化审校已经完成；实际审阅者、日期及范围应可追踪。

## 校验和故障策略

构建期阻止缺键/空值、未知键、无效 ICU、参数缺失/类型冲突、缺复数分支、重复 ID、陈旧译文、场景字段不一致与未登记的可见硬编码。源语言中文允许留在词表、用户原文夹具和经说明的对象文字白名单，不允许整目录豁免。

开发和测试环境明确报告缺失；生产故障保护按目标语言→完整 en→源 zh-Hans→当前语言安全通用提示降级，不展示裸 message ID。内置发布资源要求八语言完整，不能把降级链当作正常翻译方案。翻译中的字符串按文本或白名单富文本渲染，不执行 HTML；远端格式和变量仍严格校验。

建议新增脚本：i18n:extract、i18n:check、i18n:compile、i18n:generate-native、i18n:pseudo、i18n:verify-layout，并接入 verify。实施时锁定兼容版本，验证 FormatJS CLI 在当前 Windows 与构建机的原生 binding；必要时选择有明确支持的兼容工具版本，不能静默跳过编译。

## 实施顺序

1. 记录并保留当前未提交改动，确认各入口清单；新增基础包、语言匹配、类型和 ICU 校验，先建立失败测试。同时前置验证 SDK57 iOS widget adapter：确认 extension render、gallery/placeholder、手选偏好、App 关闭后的系统语言解析和生成原生构建切入点；未通过前不把它当作已解决，也不等翻译全部完成才暴露阻断。
2. 接通启动偏好、宿主桥和设置；迁移整套 App 界面、错误、ARIA、日期数字、用户输入。
3. 并行按 scene ID 分批迁移场景/介绍与八语言译文；统一 metadata 显示解析、动态更新和 Canvas；逐批完成文化语义记录。
4. 与文本迁移并行修复通用排版，持续用伪语言和最长真实译文验证；保留当前心愿改版效果。
5. 完成 widget v2、生成资源及两个平台 adapter；检验旧协议、隐私和语言变化。
6. 补 App 名称/法律支持与本地商店材料，完成翻译状态、全量检查、构建、浏览器矩阵和可执行的设备验收记录；上传与发版不自动执行。

不得只完成前两步后宣称“支持八语言”。每批交付附实际覆盖、验证结果与待办；最终以本设计的完成条件验收。
