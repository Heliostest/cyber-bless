# 仪式主体 Three.js 核查与图片降级清理

核查日期：2026-10-26（Asia/Shanghai）。用户确认问题出现在 iPhone / TestFlight，并要求移除图片替代 Three.js 和纯图片仪式。

## 实际发现及处理

| 路径 | 原行为 | 当前行为 |
| --- | --- | --- |
| 木鱼 `Woodfish` | 模型加载中或失败后展示 `Art` 的参考 UI 图片，点击仍计数与发声 | 只有真实模型首帧就绪后接受敲击；移除图片、弹跳及对应裁切配置；失败显示原因和重试 |
| 内置木鱼 `SceneExperience` | 只有远端 lease 的失败会交给宿主，内置失败留在图片分支 | 所有木鱼失败都进入场景错误页；错误不再被引擎吞掉 |
| 旧纸鹤／灯笼会话 `Ritual` | 图片按钮逐次递增完成进度 | 使用既有 Three.js 引擎及真实场景检查点；旧会话结算 ID、心愿关联与奖励保持兼容 |
| `useOpenRitual` | 目录缺项或引擎不支持时转到图片仪式 | 选择对应可用的内置 Three.js 场景 |
| 今日场景预览 | 加载时在场景内展示 SVG 图标 | 场景内只显示明确的加载文字，完成后显示真实画布；失败不伪装为场景 |

旧纸鹤四段存档进度 0/1/2/3/4 对应当前场景检查点 0/0/1/2/3。真实场景提交检查点 1/2/3 时，旧计数推进到 2/3/4；重复回调不能重复推进或发奖，失败重试从保存的检查点继续。旧灯笼三段与当前检查点逐一对应。此兼容映射是产品规则，不是传统数量。

目录徽章、收藏贴纸、完成页纪念图和桌面组件封面属于导航／结果展示；未把它们当作可操作场景。Three.js 模型的 PBR 贴图、纸面文字和灯光 halo 是真实模型的材质或效果，未因“图片”一词删掉。

## 全场景证据

- 覆盖 153 个场景模块及宿主木鱼，共 154 场，含目录隐藏的历史模块。
- 通过场景检查页逐场选择，在 390×844 浏览器视口确认 `ready`、非零画布尺寸和实际 WebGL 绘制调用；每场仪式主体中的 `img`、`.art`、木鱼图片降级节点均为零。记录每场 draw 次数及最大 draw 顶点数量，避免把一个空 canvas 当作通过。
- 逐场结果保存在 `artifacts/threejs-required/scene-audit.json`。此为浏览器运行核查，不等同于 iPhone GPU 或所有步骤的完整手势验收。
- 实际注入木鱼 WebGL 上下文丢失后，场景进入错误页，木鱼交互与图片节点均为零；提供重试入口。截图在 `artifacts/threejs-required/`。
- App 回归覆盖首帧前禁止计数、故障后禁止计数、重试真实引擎、内置木鱼失败传播、旧纸鹤恢复与重复检查点幂等。原有输入、完成结算、离开／返回与心愿奖励测试同步到真实场景检查点。
- 最终 App 测试 30 个文件、1081 项通过，生产构建与木鱼模型完整性检查通过。实际故障重试保留原来的 1 次轻敲，再操作后成为 2 次；重试后的图片替代节点仍为零。
- Android／iOS 离线导出校验通过，每端检查 HTML／JS／CSS 和 14 项资源哈希，其中包括内置木鱼 GLB；iOS 另校验 465 项桌面组件封面。详见 `artifacts/mobile-verification/latest.json`。
