# 场景目录默认开启

用户确认内测期间先默认打开场景目录，内测结束后再重新打包关闭。因此以一个共享源码打包开关取代原先开发环境／TestFlight 收据判断。`packages/app/src/internal-tools-config.ts` 的 `INTERNAL_TOOLS_ENABLED` 当前为 true；改为 false 后重新打包即关闭。

共享 UI 默认值、Web 权限及反馈 Host、原生初始状态及前台检查均使用该开关。使用 @wbr/app 的纯配置子路径，避免原生壳导入 DOM 模块或增加依赖。保留显式关闭时的菜单隐藏、初始路线与程序化导航保护，不修改收件后台认证、邀请码、仪式内容或玩家存档。

测试覆盖默认目录可见、显式关闭时路线拒绝、两端配置一致、iOS/Android 的开发与发布模式不依赖收据、关闭开关后不会被收据重新开启。本轮不执行签名构建或发布，手机安装包需要下一次构建后生效。

验证：App 1440 项测试、Web 构建、移动端类型/配置检查及 11 项 Node 测试通过；Android/iOS 离线导出与资源哈希均通过，iOS 477 张小组件封面及双端 171 项资源闭包验证完成。独立审阅未发现遗漏，浏览器已从“我的”进入场景目录。切换开关的测试跟随配置值，未来改为 false 无须再修改默认可见性断言。
