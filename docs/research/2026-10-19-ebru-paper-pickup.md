# 浮彩成笺：揭纸命中修正

场景 ID：`turkish-ebru-paper`。核查日期：2026-10-19。用户报告经常揭不起纸，要求改进揭纸位置。

## 原因与实际改法

旧输入只允许最前不透明命中为 `ebru-paper-edge`：纸边中央宽 .82 的小条。可见纸张宽 2.94，点击其左右侧或纸面不会开始拖动；原提示靠近前托盘边框，容易让手指落在边框上。

回归先在 284、390、1280px 下复现可见纸面的拖动无响应。修改后，最前命中的纸张正面、背面和原纸边均可开始揭纸；提示点移到纸面 `[0,.45,.7125]`。文案明确「按住白纸任意位置，向上轻揭」。无额外隐形拾取面，托盘和外部遮挡物仍不接受揭纸。原来的向上拖动、进度在收尾后提交、取消恢复、音效和震动规则继续沿用。

初次浏览器复核发现静态纸面坐标会在揭纸后留在水面，因此提示点改为随 UV `[.5,.125]` 的实际纸张顶点更新，使用每个场景实例独立的数组；先复现提示高度仍为 .45 的回归，再修正为和形变顶点一致。

## 来源与产品边界

沿用[来源卡](../../content/traditions/turkish-ebru.md)及[本日核查 C 的 Ebru 条目](2026-10-19-scene-culture-audit-c.md)：记录的土耳其文化主管部门 Ebru 正文支持液面颜料向纸张转印；UNESCO 重访人工验证未登记为已读正文。本次只扩大既有纸面的触摸命中并移动提示点，属于产品操作容错，不新增文化事实或传统规则。梳开彩纹、纸张接触液面、揭纸转印和静看流程保持原有范围。

来源 slug、App 隐藏状态、器物造型、纹样、目录和模块 metadata 均未改变，无需调整绑定；来源卡的产品呈现仍与当前流程一致。场景 README 同步实际命中与提示，并纠正旧 README 对历史索引访问和当日已读来源范围的说明。

## 验证

- 49 项场景测试通过：三种宽度各六个纸面位置的真实 Three 射线、拖动即跟手、收尾进度和反馈，保留遮挡、取消、生命周期、软卡通材质转印、可选心愿与资源释放检查。
- 3 项共享输入序列、3 项 App 暂停恢复集成通过，宿主夹具使用新的纸面提示位置。
- 首轮浏览器在 390px 鼠标、320px 原生触屏、284px 减少动态鼠标下均通过三个纸面位置的抓取、托盘拒绝、取消、跟手、反馈和完整完成流程，没有页面异常或横向溢出。报告 `artifacts/turkish-ebru-paper/pickup/browser.json`。
- 提示点改为跟随形变后，再次通过全部 49 项场景测试与 6 项集成；以 320px 原生触屏重新完成三个纸面位置，并断言提示点高度随揭纸升起且距实际顶点小于 1e-7。已查看前后持有截图，最终报告与截图 `artifacts/turkish-ebru-paper/pickup-final/`。
- 最终生产构建退出 0，保留既有大分块提示，日志 `artifacts/ebru-pickup-build.log`；场景日志 `artifacts/ebru-pickup-scene-tests.log`。本轮验证限定于相关范围，未重新执行全仓默认测试。
