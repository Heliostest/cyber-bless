# 第一批四个手作与祝愿场景

用户要求先提交、合并、推送已经完成的环境渲染改造，然后开始新 Three.js 场景。环境改造已推送到 `master`，合并提交 `d713270`。本批选择之前候选名单中的前四项。

## 范围与视觉

- `daruma-eye-painting` / 达摩点睛：红色圆身、奶油脸、双眼与描绘纹样；指尖点一目、留下目标、轻摆归位。心愿还愿入口预先显示第一目，用户补另一目。
- `mizuhiki` / 水引结愿：细纸绳、可辨认的多股结饰、礼笺；绕环、穿结、收紧并留下祝愿。使用固定引导路径，不宣称完整礼法教程。
- `milagros` / 留一枚感谢：金属薄片、心形与手形等原创小符、木质陈列架；选形、拖到挂点、留一句心意。图形不附统一功效解释。
- `phuang-malai` / 串花寄意：密集奶油白花苞、少量粉红花瓣、成环花体和两条下垂花穗；分段串花、系好、捧放并写致谢。

保持现有奶油/薄荷 UI、圆角舞台、当地昼夜天空和 Kenney 自然环境；使用 `toon-soft` 的柔和哑光体积。每个主体占手机画面的主要区域，所有完整物件在 320–430px 宽度可辨认。参考对应 `content/traditions/<id>.jpg` 和 `.md`；照片只用于观察，不下载或混用游戏资产。

## 状态与接入

每场景为独立动态加载模块，提供 `SceneModule` 的 `meta/create`。保留现有整数进度 0–3 契约；恢复保存步骤不重复发送 progress/saveWish/complete。屏幕外暂停不接受输入，减少动态效果不阻碍动作完成，按钮与真实器物拖动均能完成流程。

四项加入内置目录和心愿型每日候选、引擎注册、独立 SVG 图标与舞台色彩。小物仍使用现有 `kind: scene`、`sceneId`、`wishScene`；无需扩大核心 RitualId。上下文新增可选 `returning`，由已校验的还愿入口传入，达摩据此补第二目。保存的心愿与场景关联继续使用现有 `sourceSceneId`，还愿与小物花费采用现有幂等结算。

选中的小符通过 `SceneRecord.variant` 保存在既有存档，复开与恢复后保持同一物件；此可选字段与 0–3 步骤独立，旧存档无需迁移。运行时使用 `initialVariant/onVariantChange`。每日主场景池取祝福与心愿候选两者的最大长度，保证新增的尾部场景也能被选中。

许愿与还愿的文字均为产品改编，不声明仪式效力；达摩常规会话不自动补第二目。指针从器物开始才占用触摸，空白区域保持页面滚动，多指与取消不推进进度。

## 验证

单元/集成：三个步骤、暂停、恢复 0–3、减少动态效果、重复输入的幂等、退出后无事件、达摩首次/还愿分支、书写保存。全项目 `npm test`、Web build、两端离线导出校验。

浏览器：四场景手机与桌面截图、直接按钮与实际拖动、心愿/还愿入口、320px 取景、天空失败回退、反复打开与 GPU 资源释放。独立代码审查后修复实际问题。

## 实现与检查记录

- 几何参照仓库的四张工艺照片与主题卡，全部为代码创建的原创模型。文化描述参照 [群马达摩介绍](https://www.visit-gunma.jp/en/spots/takasaki-daruma/)、[日本政府水引工艺介绍](https://www.gov-online.go.jp/eng/publicity/book/hlj/html/202312/202312_05_en.html)、[Lam Museum 的 Milagros 介绍](https://lammuseum.wfu.edu/2024/10/mexican-milagros/) 与 Phuang Malai 主题卡中的学术来源。
- `npm test`：635 个测试通过。`npm run build`：通过。保留原有 React 测试的 act 提示和 Three.js 公共分块大小提示。
- 四个模块的行为测试覆盖恢复、真实几何射线交互、取消、多指、按钮、暂停与书写。独立审查发现并修复了场景外第二指、第二指按钮绕过以及宿主暂停时停止 RAF 却未通知场景清理手势的问题。
