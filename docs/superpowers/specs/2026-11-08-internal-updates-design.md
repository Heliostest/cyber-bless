# 内测 App 的 Three.js 内容更新

日期：2026-11-08。用户要求在现有后台基础上，减少每次修改场景后重新打包的次数；已明确第一阶段只给本人和内测人员使用。

## 目标与范围

在已安装的 App 内更新网页端场景代码和资源，保留存档、反馈、离线启动和原生桥。首次需安装一次含接入能力的内测包，之后同一原生运行时的场景手势、动画、材质、shader、模型、纹理、音频及文案可通过更新包分发。原生模块、权限、Widget 原生实现、原生依赖和不兼容存档变化仍需新安装包。

正式用户保持现行随包发布策略。本次不把旧远程数据目录恢复为正式 App 的内容入口，不凭下载机制绕过文化审阅或正式发布规范。

## 实现选择

采用已安装 Expo SDK 对应的 `expo-updates` 客户端，在现有 Node 反馈服务内增加兼容 Expo Updates v1 的分发接口。使用固定 HTTPS 地址、独立内测 runtime/channel 和本地管理入口；不购买或依赖托管更新服务。整套网页 JS 和资产按不可变版本导出，客户端复用已校验文件。更新单位是兼容的网页应用快照，不承诺对任意单个 TypeScript 文件动态打补丁。

仅发布 GLB/JSON 的旧通道不能修复手势逻辑；手机浏览器在线预览也不能等价验证现有原生桥和离线 App，所以均不能单独满足本需求。自制任意脚本注入会重新承担加载、兼容、失败恢复和生命周期控制，优先复用 Expo 的原生更新运行时。

用户已确认内测范围及按本方案实施；原生安装包的创建和分发必须沿用项目正式入口与冻结来源规范。

## 客户端

- 新内测构建开启专用更新配置，正式构建不接入内测更新地址。运行时版本覆盖真实原生依赖和桥契约，防止错误版本装载。
- 手机内测工具显示当前版本、可用版本、说明、下载/校验进度与失败原因。沿用邀请码鉴权，无共享邀请码进入源码或构建环境。
- 手动检查、下载与明确的“应用更新”动作分开；仪式运行中不重建 DOM，不中断保存。应用前完成存档队列写入，退出体验再重载。
- 保留嵌入版与已确认版本，下载失败、断网或不兼容时保留当前可运行版本。实施核查发现 DOM 错误不一定触发 Expo 原生启动恢复：宿主另提供前台就绪超时、渲染错误检测与独立原生修复入口，供管理员在线发布修复/回退后检查、下载、手动应用；损坏 DOM 的离线自动回退尚不能保证。反馈诊断包含真实更新 ID 与源码版本，不能只报告原生构建号。
- 原生增加/修改桥时提高 runtime；旧包无法凭后台开关获得新原生能力。

## 静态资源

当前模型、HDR、字体、图标和声音经 `public` 目录随包携带；Expo 当前文档明确 public 不随更新分发。将受控资产改为 Metro 注册资产，并提供已验证路径到本地 URI 的映射。网页资源加载器、背景树/HDR、字体及 iOS 声音读取统一使用该映射，兼顾嵌入启动与更新目录。禁止只更新代码却仍加载旧 public 文件。网页端继续使用现有资源路径。

每次导出校验所有资产字节数、SHA-256、路径、HTML/JS/CSS 与平台/runtime 身份。缺文件、路径穿越、外链依赖、原生契约不匹配或未完成导出不能进入发布列表。

## 后台和发布

- 接收端继续监听 4318，经现有固定隧道分发；4319 管理端保持仅本机。增加内测更新管理区，不向公网暴露发布、回滚、源码文件或终端执行功能。
- CLI 从受审阅源码准备不可变导出；版本记录 commit/tree、平台、runtime、更新 ID、时间、说明和资源哈希。只将白名单导出文件纳入包，凭据、反馈和工作区文件不进入产物。
- 管理员选择已验证产物发布到内测通道；邀请码只能获取兼容更新、不能上传或发布。发布采用原子切换；旧版本及必要资产保留。
- 清单签名与校验纳入客户端信任根；签名私钥在 Git 外部，公钥证书可以随包发布。不打印私钥、邀请码或含秘密的命令参数。
- 回退旧内容时生成新的更新身份/时间，避免原生数据库按较新日期继续启动已撤回版本；可回到嵌入版。管理界面展示实际发布版本与回退来源。
