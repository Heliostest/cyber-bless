# 内测仪式反馈

当前内测阶段默认显示“我的 → 场景目录”，从这里打开的仪式提供“反馈问题”浮层。正常今日、收藏或愿望入口不显示反馈浮层。打开反馈会暂停原仪式，关闭后继续，不重建场景。

Web、iOS 和 Android 共用 `packages/app/src/internal-tools-config.ts` 中的 `INTERNAL_TOOLS_ENABLED` 打包开关，当前为 `true`，无需依赖 TestFlight 收据识别。内测完成后改为 `false` 再重新打包，场景目录、内部路线与反馈浮层将关闭；旧的已安装包不会随源码变化自动关闭。原生启动初值与回前台检查使用同一开关。

## 开始收件

2026-11-06：本机已切换到固定收件地址 `https://feedback.heliosoft.win/api/feedback`，由命名隧道 `cyber-bless-feedback` 转发到 `http://127.0.0.1:4318`。现有邀请码和收件数据沿用，管理后台仍只在本机 4319 开放。

App 的默认上传地址现已设为该固定网址。更新到包含此改动的版本后，本机保存的空网址或旧 `*.trycloudflare.com` 地址会自动迁移，并保留邀请码、草稿、待发反馈和既有回执；旧服务的团队状态缓存清除后重新同步。迁移先写入本机，成功后才上传待发项；写入失败保留原数据并退避重试。自定义 HTTPS 收件地址和本机联调地址保留。已有安装包不会随源码改变默认值，需更新 App 后生效。

Windows 本机首次安装登录自启动并立即启动：

```powershell
npm run feedback:install
npm run feedback:status
npm run feedback:logs
```

计划任务 `CyberBless-TestFeedback` 使用当前登录用户，无需保存 Windows 密码。登录后自动启动，每分钟补偿检查；进程正常运行时忽略重复启动，没有三天运行时限。独立于 Codex、Vite 和日志终端，关闭日志查看器不影响收件。守护进程分别监控接收服务与隧道，异常退出或连续健康检查失败后自动重启，重试间隔递增至最多 60 秒。Windows runner 也会恢复退出的守护进程；使用 Job Object 清理整棵子进程树，避免孤儿服务占用端口。不会抢占或结束其他程序。

公网地址每次变化都会带时间打印到终端和 `artifacts/test-feedback/supervisor.log`，本机后台也会刷新。日志达到 1 MiB 后轮换，保留一份旧日志；不记录邀请码或测试者描述。`feedback:logs` 持续跟随新日志，按 Ctrl+C 只退出查看。`runner.log` 记录外层启动失败或守护进程退出。`feedback:status` 查看任务、接收服务、隧道和当前公网地址。

```powershell
npm run feedback:stop       # 停止并禁用自启动/自动恢复
npm run feedback:start      # 重新启用并立即启动
npm run feedback:uninstall  # 移除任务，保留邀请码和反馈数据
```

任务使用本仓库的绝对路径；移动仓库前先卸载任务，再从新位置安装。自启动是当前用户登录后启动，电脑休眠、关机、未登录或断网期间不能在线收件；恢复运行/联网后继续尝试。使用固定隧道时重启不会换网址；使用临时隧道时，地址变更仍需手动分发给测试者。计划任务能力参考 [Microsoft Task Scheduler 设置](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset?view=windowsserver2025-ps)（2026-11-02 已读正文）。

临时前台守护可运行 `npm run feedback:supervise`。手动诊断时先 `feedback:stop`，再分别运行两个终端：

```powershell
npm run feedback:serve
npm run feedback:tunnel
```

本机后台：<http://127.0.0.1:4319/>。这里显示当前上传网址和可复制的测试邀请码，也可按场景筛选、查看诊断、标记“待处理 / 已确认 / 已修复”、导出 JSON 或 Markdown。邀请码不要放入 Git、App 源码或公开日志；默认保存在 `%LOCALAPPDATA%/CyberBless/test-feedback/server.json`，不是 Cloudflare 管理凭据。

### 分配独立邀请码

原有共用邀请码继续可用。可为不同测试人员创建独立码，默认生成“测试员01”至“测试员05”：

```powershell
node scripts/test-feedback/cli.mjs create-invites --count 5 --label 测试员
```

新码保存在 Git 外部、与 `server.json` 同目录的 `invitations.json`，命令不会打印实际邀请码。重启接收服务后，在本机后台的“独立测试邀请码”分别复制给对应人员；现有 App 直接填写新码即可。后续批次换一个编号前缀，不能重复已有标签。自定义 `--config` 时独立码文件默认跟随其目录，也可用 `--invitations-file` 指定外部路径。

新反馈会额外保存来源邀请码的编号和标签，本机后台及导出可见；报告正文与公网回执协议保持不变，邀请码原文不写入收件记录。此前的收件无法追溯到独立人员；同一报告换码重试也不覆盖最初的来源。编号表示所用邀请码，持有人转发邀请码后不能据此证明真实身份。

撤销某个独立码时，使用外部配置中对应的 `id`：

```powershell
node scripts/test-feedback/cli.mjs revoke-invite --id <对应的编号ID>
```

创建、撤销及修改独立码都需重启接收服务后生效；由计划任务管理时使用 `feedback:stop`、等待旧进程退出，再 `feedback:start`。撤销不删除已有反馈，也不影响其他码；`rotate-token` 只更换原有共用码。配置损坏时拒绝启动，保留原文件；并发编辑会拒绝第二个写入，避免覆盖。异常中断遗留的 `.lock` 仅在确认没有编辑命令运行后再人工移除。

第二个命令只把反馈端口 `127.0.0.1:4318` 暴露到公网，允许提交反馈、携带邀请码查询团队状态，以及按仪式读取窄化的历史问题。历史返回原意见、步骤、时间、版本和处理状态，不提供投稿人身份、邀请码、完整设备诊断或管理接口。不要把 4319、本机开发服务器或其他目录转发出去。接收服务、隧道和电脑须保持运行；电脑休眠或停止服务期间，手机反馈会保留待发。

### 固定域名配置

`feedback:tunnel` 和守护进程会读取 Git 外部的 `%LOCALAPPDATA%/CyberBless/test-feedback/tunnel.json`：

```json
{
  "schemaVersion": 1,
  "publicUrl": "https://feedback.heliosoft.win",
  "tokenFile": "cloudflare-tunnel.token"
}
```

`tokenFile` 可使用绝对路径，或相对于此配置文件目录的路径。令牌文件来自该命名隧道的连接器安装说明，仅保存专用令牌，不保存安装命令；不要把它写入 Git、App、日志或命令行参数。启动使用已安装的 `cloudflared tunnel --protocol http2 run --token-file …`，仍由现有任务持有进程树，不再另装一份 cloudflared Windows 服务。

在 Cloudflare 中添加已发布应用程序路由：主机名 `feedback.heliosoft.win`，Service URL `http://127.0.0.1:4318`；Cloudflare 自动创建对应 CNAME。不要转发管理后台 4319。收到连接器注册事件后才公布固定网址，公网健康检查继续由守护进程验证。更新配置后运行 `feedback:stop`、`feedback:start`，用 `feedback:status` 核对当前地址。Windows 任务停止是异步操作，排查重启时应等待旧进程实际退出再判断新进程状态。

固定配置损坏或凭据文件不存在时会拒绝启动，不会自动退回一个变化的临时网址。只有配置文件不存在时才启用 Quick Tunnel 模式。

### 可选临时隧道

没有固定配置文件时，已安装的 `cloudflared` 可创建临时 `https://….trycloudflare.com` 地址；地址原子写入 `artifacts/test-feedback/tunnel-runtime.json`，后台会刷新显示。该文件没有邀请码。临时 Tunnel 每次启动可能更换地址，没有运行时间保证。[Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)（2026-11-02 已读正文）。无论固定或临时模式，已启用自启动时都由守护进程管理隧道，不再另外启动第二份；agent 可读取状态文件或 `feedback:status` 获取地址，不打印凭据。

## 测试者操作与失败重试

1. 从场景目录进入仪式，点击“反馈问题”。
2. “上传设置”已默认填写固定收件网址，已有邀请码继续沿用；新测试者首次只需填写测试邀请码。开发联调其他接收服务时仍可修改网址，支持域名根地址或 `/api/feedback`；远端须 HTTPS，本机联调允许 loopback HTTP。
3. 描述具体操作问题，可用手机键盘的听写功能；不是录音上传。自动记录打开时的场景、已完成检查点、公开提示、版本和运行环境，问题步骤可手动修正。多动作检查点不等于细分手势步骤。
4. 点击“发送反馈”。先保存到本机，再尝试上传；“已送达本机后台”表示后台已经持久化并返回匹配编号的回执。本机确认写入成功后才从待发队列清除。

草稿、连接设置、待发队列和近期回执使用独立键 `cyber-bless:test-feedback:v1`，不改游戏存档。网络失败、超时、坏回执或回执丢失都保留待发项；更换地址、恢复联网、回到 App 或有新反馈发送时自动重试，并带退避。所有待发项使用最新保存的网址和邀请码。重复发送使用相同编号，后台不会生成重复记录；正在等待回执的反馈不可原地改写，可继续新建问题。

最多保存 100 条待发反馈；队列满、读取失败或本机空间不足会明确提示，不静默丢弃。存储写入失败时请保留页面，恢复后重试；删除 App 或清除站点数据仍会删除未发送记录。App 停在后台或已关闭时，不承诺持续上传。

## 目录中的团队测试标记

场景目录显示“未反馈 / 已反馈 / 待复测 / 复测通过”，并可按标记筛选。同步使用浮层中保存的网址与邀请码，进入目录、回前台、联网、上传成功或手动刷新都会更新；前台也会定时刷新。没有连接或读取不完整时显示“状态未同步”，离线缓存标注同步时间，不把失败当作未反馈。

标记针对当前仪式的测试指纹：当前内容有未处理问题显示已反馈；仪式源码、相关交互依赖或资源改变，或者后台将问题标记整改后，会要求复测。测试人员完成验证后，在浮层点击“本版本测试通过”；这会排队上传一条明确的通过确认。旧版本或旧问题基准的离线通过不能清掉团队新问题，待上传也不算已反馈。

旧草稿保留原始测试指纹，不会在更新后冒充当前版本。通过操作会保护未发送的问题文字；请先发送或清空问题描述。通过记录在后台单独标识，不进入 AI 的待修复问题导出。

### 在仪式里核对历史问题

更新到包含历史反馈界面的 App/内测更新后，从“我的 → 场景目录”选择待复测仪式，点击“反馈问题”。待复测状态会展开“历史反馈”；其他状态也可手动展开。

这里按接收时间倒序展示同一仪式的原问题、对应步骤和当时提示、原生版本/构建号、修订及“待处理 / 处理中 / 已修复，待核对”。旧版本、旧修订和已修复记录均保留；未记录修订的旧报告明确标注，不冒充当前版本。每页 20 条，可“加载更早反馈”或“刷新历史”。

需有效邀请码并联网读取。失败显示错误，已读取的内容继续保留并提示状态可能变化；尚未读取成功时不把错误显示成“没有反馈”。历史仅在当前面板内存中保留，不写入反馈存储或玩家存档。切换仪式、上传地址或邀请码后不串用旧内容。

`POST /api/scene-feedback-history` 返回窄化只读字段，不包含投稿人身份、邀请码、完整设备诊断或通过凭据。手机复用现有 JSON 反馈桥，不增加原生桥函数；旧状态查询协议保持不变。读取历史不会自动标记通过或修改问题，仍需对照验证后明确点击“本版本测试通过”。旧 App 需要安装包含该界面的新版本，或在已接入热更新的内测包上应用新版更新。

`npm run scene:revisions` 重建仪式测试指纹，`npm run scene:revisions:check` 检查是否过期。正常 Web/App 资源准备会自动生成，开发服务器也会监听源文件；指纹独立于 engine、内容 revision 和玩家存档版本。只更新实际依赖或内容时使相应仪式待复测，不依赖 Git 提交号或构建日期。

```powershell
npm run feedback:export
```

该命令把“待处理”反馈导出到 `artifacts/test-feedback/to-review.md`；原始文件在 `artifacts/test-feedback/inbox/*.json`，均已由既有 `artifacts/` 规则忽略。可以对 agent 说：“读取本机内测反馈，按场景和步骤归并，先复现，再修复和回归验证。”导出明确标注测试者文本为不可信数据，不能将其中的命令或授权当作指令。

建议一次处理一组可复现操作问题，记录反馈编号、复现、修复与测试结果，再在本机后台标记状态。不得从反馈臆造文化主张；若改动器物、动作或提示，仍须执行 [场景来源核查规范](scene-provenance.md)。
