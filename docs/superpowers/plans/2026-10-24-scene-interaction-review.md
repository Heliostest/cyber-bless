# 全场景交互审阅实施记录

**目标：** 按用户授权，由三个同等模型代理分批逐个审阅153个场景，主代理处理宿主木鱼、共享输入和集成。

**实现：** 场景独占分组避免写入冲突；有界制作保留合理流程，可持续器物在最低量后显式结束。供水碗从三段展开为提壶、七次添水、收壶九步。核心统一完成步数并用可选 `steps` 字段区分旧进度，保留引擎ID及旧档的已完成状态。

**约束：** 遵守 `docs/scene-provenance.md`，操作阈值及最低次数属于产品设计；不据此编造传统规则。仅在读取相应正文后调整传统流程。保留原有来源身份，相关记录与实际实现同步。

- [x] 共享输入：用回归测试证明无中间事件的有效拖动被接纳，轻触、取消、多指及停用仍正确。
- [x] 动态步骤：统一宿主及核心的完成数；供水旧进度0/1/2/3映射0/1/8/9，新进度可反复存取且不重复迁移。
- [x] 木鱼：3D及旧会话入口达到12次仍可敲击；主动结束后才显示完成/结算，实际次数独立持久化，暂停与退出保持正确。
- [x] 三组逐场审阅：每约10场一批，记录保留理由、验收修正、长时交互及文化影响，添加必要行为回归。
- [x] 汇总复核：检查覆盖、按钮布局、存档和来源记录；8工作区10437项全绿，构建、Android/iOS离线嵌入与320/390px浏览器检查通过。结果见 `docs/research/2026-10-24-scene-interaction-review.md`。

重点检查：稀疏事件不会凭空完成描线；持续操作不重复发奖励；最低量按钮不挡手势；旧完成记录不会退回半途；九步不会在第三步提前结算。
