# 场景来源与文化关联核查规范

本规范适用于后续所有新增、修改、审阅和发布的场景。目标是让每项文化主张都能追溯到对应证据，将产品创作如实归给产品。2026-10-19 的[全场景核查](research/2026-10-19-scene-culture-audit.md)提供纠错案例，本文件是持续执行的项目标准。

## 1. 核查实际场景与每项主张

先阅读实际实现与用户可见内容，列清器物、材料与部件、动作及完成条件、空间、对象、场合和文字表达。新增场景先写拟呈现内容，不能先选一个地域或宗教名称，再寻找能搭上关系的背景。

分别核对下列主张；一条来源只能证明其中一部分时，不得扩大其支持范围。

| 主张 | 必须核对的对应关系 |
| --- | --- |
| 器物与工艺 | 来源确实讲这件物类、材料、部件或技法，而非同地区另一件器物或一张无关照片 |
| 地域与社群 | 具体地点、社群、时代及使用者；一件地方馆藏或现代作品不能证明整个民族自古如此或独有该工艺 |
| 动作与流程 | 谁对什么物件做什么、在何种条件下；局部手势不能自动拼成完整传统仪式 |
| 场合与规则 | 日常、节庆、礼赠、祈愿等具体语境；次数、期限、先后、资格和禁忌不能由产品节奏推导 |
| 意义与信念 | 来源中参与者或作者如何解释；区分地方信念、文学叙事、研究解释与产品赋予的情绪含义 |
| 历史与传承 | 起源、年代、连续传承和当代变化各自有何证据；当代作坊、旅游活动或遗产名录不自动证明古代起源 |

“寄暖”“片刻安静”等可以表达用户此刻的感受，但不能因此写成“当地人自古以此祈求温暖／安宁”。文学作品可证明文学母题，不能单独证明现实习俗或仪式步骤。

每次修改场景都先判断文化影响。仅修复生命周期、性能或布局且未改变上述内容时，可引用已有核查记录并说明未改变文化主张；涉及器形、动作、文案、寓意或来源变化时，必须重新核对受影响的主张，不机械重查无关条目。

## 2. 使用直接对应、实际读过的证据

优先采用社区与传承者自述、宗教机构对自身实践的说明、博物馆器物及策展记录、文化遗产主管机构的项目资料、官方申报原件、原始文献和研究。机构发表的采访可作为受访者的第一手材料；机构综述仍应按综述使用，不因域名官方就把所有内容称为原始证据。

百科、新闻转述、旅行介绍和商业文案可提供线索或交叉参照，不能独自承担超出其证据的起源、统一规则或神圣寓意。博物馆商店的当代工艺活动只能证明所述活动，不能据此推成古代传统。已有来源卡、设计规格、Notebook／AI 摘要、模型生成结果、代码和通过的测试均不是新增文化事实的独立来源。

必须打开并阅读与主张有关的正文、馆藏说明或原件。证据记录至少包括：

- 来源标题、发布机构／作者、完整 URL；有发布日期时保留原日期，另记实际核查日期。
- 实际阅读的相关段落、章节或 PDF 页码，简述它支持哪项主张、不能支持什么。
- 读取状态：已读相关正文、部分可读、仅索引／摘要、失访及具体原因。不得把部分可读记成已通读全文。

验证码、403／404、超时和搜索摘要不能登记为已读正文。可改读同一机构可访问的官方文件或另一条直接证据；仍无依据则收窄或撤下相关主张，并记录缺口。未找到证据不等于证明任何地方都不存在相似做法。

不以链接数量、官方标签、名录身份或旧评估分数代替对应性判断；一条直接材料足以支持的有限事实，不强凑第二条。遇到冲突先核对术语、观看视角、地域、年代及语境，再决定是否需要补证。某社群的叙述不能压成全球统一规则，也不能用多数说法抹去已证实的地方差异。

## 3. 将传统事实与产品创作分别记录

源卡的“文化与器物／公开实践”只写证据支持的内容；“本产品呈现”说明实际简化、替代与新增表达。颜色、原创纹样、展架、辅助按钮、动画、完成反馈、静看、计时、可选留言和回访等，不因出现在场景里就成为传统要求。

“手机互动适合度”“若做成互动”“评估草稿”和产品计划始终是设计判断，不是传统流程或文化许可。历史提案保留时须标明其状态，不得继续把未实现的提案写成当前操作，也不得用提案作为新事实的引用依据。用户界面按眼前体验自然表达；不要求堆放“产品原创／非真仪”等研发标签来弥补错误关联。

有真实器物或工艺关联的简化体验可以保留来源，不必逐尺寸复刻馆藏、照搬匠人纹样或表演完整仪式；但不得把自行拼接的机制、动作组合或寓意称为传统。图片授权和技术可行性须分别核对，二者都不能证明文化关联。

如实保留已证实的宗教礼敬、占卜、求愈信念、婚恋或纪念语境。应用可以采用自省提醒、日常感谢等表达，但不得将真实传统重新定义成“本来只有心理舒缓／装饰意义”。信众相信的效果应归于其信念，不写成产品保证。

## 4. 按证据选择来源与分类

1. **直接关联成立：** 复用已经对应器物、工艺或具体实践的专卡；若总卡确实直接支持本场景的选定实践，也可使用，并标明具体证据。先搜索现有卡片，避免重复建卡。
2. **地域成立但旧卡对象错配：** 补对应专卡，或修正确有对应内容的现卡，再更新绑定。不得以“同地区”“民族背景”“只是导航索引”为由继续借用无关宗教、祭典或民俗总卡。
3. **仅部分主张成立：** 保留有据的器物关联，删除或收窄无据的起源、步骤和寓意，把应用新增部分写入产品呈现；不因动作简化就一律抹去真实文化来源。
4. **当前组合缺乏可成立的传统关联：** 保留合理的产品体验，取消传统身份与寓意背书，按 `product-original` 处理；不为填满来源字段而换一个同样无据的文化。

`product-original` 的实现要求：

- 场景注册表和模块 metadata 使用已有的 `PRODUCT_ORIGINAL` 常量；有对应模块时两处保持一致。
- `packages/core/src/daily-scenes.ts` 的宿主条目省略 `traditionSlug`，不能把 `product-original` 当作一张传统来源卡。
- 不为该组合伪造传统卡；研究记录说明为何解除关联。旧卡可保留其有证据的研究内容，但不能继续承担该场景的来源职能。
- 保持技术 ID、引擎标识、存档与历史记录兼容。若可见标题仍暗示无据地域或寓意，应修正标题，并同步适用的原生组件与展示目录。

来源身份必须在实现前确定到可成立的范围；核查不通过的主张不能以传统事实进入合并或发布。可通过补证、收窄文字、拆分来源或改为产品创作完成修正，不以免责声明代替修正。

## 5. 在项目内保存可复核记录

有文化关联的场景在 `content/traditions/<slug>.md` 维护器物／实践事实、实际产品呈现与参考来源。缺乏传统绑定的产品创作在场景 README 或研究记录中说明其归属，不制造文化来源卡。

在场景 README 或 `docs/research/` 保存以下记录，并互相链接。可以沿用已有格式，但不能只留一串 URL：

```markdown
场景 ID：
核查日期与本次变更：
实际器物／材料／动作／场合：
拟陈述的文化主张：

| 主张 | 来源标题、机构、URL 与相关段落／页码 | 实际读取状态与日期 | 支持范围及不能外推的内容 |
| --- | --- | --- | --- |

传统事实：
产品简化与新增表达：
缺口、差异与处理：补证／收窄／撤回／不适用及具体原因
最终来源 slug 或 product-original：
同步修改的文件与验证结果：
```

记录必须对应最终代码和文案。缺口需要具体到主张，不能用“待考据”笼统掩盖仍在产品中使用的断言；纯产品创作无需虚构传统证据。不要将一个已读来源扩写成全部参考都已核验。

## 6. 新增、修改及合并前核查清单

- [ ] 实际器物、材料、动作、对象、场合与完成条件已逐项对照；无把产品构思反向当作传统的情况。
- [ ] 每项新增／变化的文化主张有对应的已读证据，或已收窄、撤下；未涉及文化主张的技术改动已说明并引用既有记录。
- [ ] 无同地区、同民族、视觉相似或“导航索引”式错绑；已查找并优先复用合适专卡。
- [ ] 寓意、规则、起源及节期未过度外推；真实信仰背景未被产品情绪表达替换。
- [ ] 来源卡、研究记录和场景 README 区分传统事实与产品新增，并如实记录读取状态及缺口。
- [ ] 宿主目录、注册表、模块 metadata 的来源分类一致；所有绑定的源卡存在；适用的可见标题与原生组件已同步，技术 ID／存档保持兼容。
- [ ] 用户介绍、提示、状态和结束语与最终核查一致；无证据的承诺或背景已直接修正。
- [ ] 根据实际改动运行相关测试及构建，需检查显示时补浏览器验证；技术检查与人工来源审阅分别报告。字段一致或页面无错不等于文化事实已验证。

审阅者以这份清单检查最终改动，而不只看来源链接是否存在。未通过项须修正或说明为什么确实不适用，不能靠“致敬”“原创转译”或旧稿已批准放行无据的传统主张。

## 7. 已纠正的案例

| 情况 | 本项目采用的处理 |
| --- | --- |
| 白族扎染借本主信仰、西西里日常木车借圣人节庆典花车 | 换成对应工艺专卡，保留可证实的地域关联 |
| 空水面倾注、放花瓣与合十拼成上座部传统；翻手记借捷克朝圣路线背书 | 解除传统绑定，保留产品体验 |
| 月老赤绳文学推成绕架、合扣与自爱寓意 | 文学留在研究卡；当前红绳手作归产品创作 |
| 达摩任意回访就等同事成、御守统一一年到期 | 按实际机构来源恢复条件与差异，不把应用回访机制说成传统规则 |
| 纸鹤简化折叠和个人留言、草编花园的和谐寄寓 | 保留有证据的文化内容，区分应用简化，不因纠错而删除真实关联 |

每项的原关联、读取状态、纠正依据与实现结果见[2026-10-19 来源审阅](research/2026-10-19-scene-culture-audit.md)，不能将案例概括反过来替代未来新场景的逐项核查。
