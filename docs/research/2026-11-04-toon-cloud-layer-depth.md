# 全场景云层可见层次评估与调整

后续布局：用户要求进一步靠近顶部，当前云带已整体由 72 上移至 48 CSS 像素，层间色阶/柔边和相对距离保持。以下全场景计数是 72 像素版本的评估快照；[当前间距与验证](2026-11-04-toon-cloud-viewport-anchor.md)。

最新视觉调整：根据澄清，横向恢复原尺度，改为纵向拉开，顶部仍为 48 像素；提亮云色和减轻日景远雾继续保留，见[布局澄清与通透感记录](2026-11-04-toon-cloud-airy-layout.md)。下方全量计数仍为当时版本的历史快照。

日期：2026-11-04（Asia/Shanghai）。用户要求评估所有场景中的云层可见层次，并适度增强可见云层之间的层次感。

## 评估方法

检查 App 当前全部 91 个可见场景，在 390×844 浏览器窗口、初始检查点与减少动态的时间 0 状态分别保存调整前后实际场景截图。85 个共享日景逐层检查，五个夜景与一个海岸场景继续保留原背景。这不是每个检查点、变体和每一帧的穷举。

`scripts/audit-toon-cloud-layers.mjs` 在各场实际相机、前景和逻辑画布尺寸下测量：保持原本六层透明度和所有前景遮挡，把云材质临时克隆成黑/白探针，进行一次黑基准和六次逐层白探针渲染。两次图像差提供各层经过其他云和前景遮挡后的可见贡献，不把“有六个平面”当成“看得见六层”。测量结束恢复原材质和渲染状态，销毁探针资源；退出另外验证正式云的七个资源释放。

本次诊断将贡献至少 20/255 的像素归给贡献最大的层，至少占云像素 1% 且不少于 24 像素、垂直范围至少 3 像素才记为一层。该数字是统一的比较尺度，不是人眼分辨能力标准；颜色和构图仍通过实际截图复核。探针使用线性、无色调映射的前向渲染，避免把配色深浅误认为透明可见面积；实际截图保留 App 的默认呈现。

评估区分可辨云带、多层可见、天空狭窄/前景遮挡及夜景/海岸保留。云层少不自动认定为问题；俯视、木梁、树冠和地面遮挡不通过改相机或盖住前景解决。审计运行冻结对应版本的云源码并屏蔽开发 HMR，保证调整前后不混用。

## 实际调整

- 保留已确认的 **72 CSS 像素上沿**、原相机、六个远处深度代理、主体遮挡和场景范围。
- 原版常用 350 像素画布中，六层独立上沿为 72、116、154、175、206、233 像素；靠前的层容易落在地平线后。现改为逐层计算柔边轮廓上沿，以 72、88、105、123、142、162 像素排列，收拢有效云带，保留动态形状与各层速度。
- 配色从较偏蓝的远层渐变到较亮的近层，扩大有效明暗范围；不加描边、光晕或额外装饰。
- 边缘由远到近从 6、5、4、3、2.25 到 1.5 CSS 像素变清晰，避免原近层约 11 像素的可见过渡融成一片。不透明度由 .90 渐变至 .98，减少多层叠加后的混色。
- 根据宽度与动画时间拟合各层，缓存和 GPU 资源所有权保持；暂停、减少动态、预览时间冻结继续沿用现有环境时钟。
