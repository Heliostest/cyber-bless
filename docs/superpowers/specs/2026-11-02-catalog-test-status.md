# 场景目录团队测试状态

目标：内测人员从目录区分未反馈、已反馈、更新/整改后待复测，以及明确复测通过的仪式。以共享后台收件为准，不能把本机待发反馈当已送达，也不能把无法联网当未反馈。

状态优先级：当前仪式测试指纹有未解决问题→已反馈；当前指纹且当前问题基准匹配的明确通过→复测通过；有历史反馈、指纹改变或整改尚未确认→待复测；后台确认没有记录→未反馈。没有有效同步结果→状态未同步；旧结果可展示但必须标注离线/缓存。

用独立的 sceneTestingRevisions 指纹记录实际场景源代码、交互依赖、相关资源和文案，不改技术 ID、engine、内容 revision 或游戏存档。只改某个场景时仅它及实际依赖者受影响；共享交互变化可要求相关场景重新测试。日期、Git HEAD、README、日志等不能改变指纹。生成器纳入构建与校验，开发改动时可同步刷新。

协议 v1 向后兼容：FeedbackReport.scene.testingRevision?、result?:issue|pass、reviewToken?。旧反馈仍可读取及重试，不得补填当前版本。通过确认新建不可变编号并快照当前版本、当前问题基准，不覆盖未发送问题描述。明确通过才关闭测试循环；离线旧基准通过不能清除团队新问题。

公网只新增已鉴权 POST /api/scene-status，查询 {schemaVersion:1,scenes:[{id,testingRevision}]}，返回 {schemaVersion:1,generatedAt,scenes:[{id,testingRevision,state,issueCount,openIssueCount,reviewToken,latestFeedbackAt?}]}。不返回原始描述、设备信息或报告 ID。reviewToken 仅由该场景问题身份、版本和实际处理状态计算，不包括通过记录或刷新时间。损坏记录导致状态不完整时明确失败，不能返回未反馈。

客户端缓存与刷新按接收地址/邀请码隔离；切换连接、App 回前台、联网、发送成功、进入目录或手动刷新时同步。慢旧请求不能覆盖新连接状态；没有后台数据时不展示伪造的未反馈。目录提供状态筛选、待上传数量/提示、刷新与同步时间，继续保留既有搜索和分页。

复测确认在反馈浮层新增“本版本测试通过”操作，沿用持久队列/严格保存回执。没有当前可信问题基准时禁用；有未发送的问题输入时保留原文并明确处理，不能悄悄覆盖。队列恢复旧反馈版本，后台区分问题与通过，AI 待修复导出不包含通过记录。

文化影响：仅内测协作状态与诊断元数据；不修改器物、动作、完成条件、文化主张或存档语义，沿用 docs/scene-provenance.md。

验证：聚合优先级、当前/旧版本、已整改/明确通过、新问题使旧通过失效、离线旧通过与邀请码切换、损坏记录、旧存档兼容、源代码指纹隔离、目录筛选/断网/缓存/待发、原有反馈可靠队列、Web 与移动端导出。Windows 不宣称 Swift 或 TestFlight 真机验收。
