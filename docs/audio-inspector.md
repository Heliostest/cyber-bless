# 界面音效覆盖检查

2026-11-03 新增，仅 Web 开发服务器可用。正常启动 `npm run dev`，打开主 App 左下角「调试台」，开启「界面音效覆盖」。无需 URL 参数，不恢复旧 Shader 调试覆盖；生产 Web 和 Expo 原生宿主不注入入口。

- 已声明声音的可见操作出现虚线轮廓和右上角喇叭；鼠标、触摸或键盘可试听。角标是独立按钮，试听不执行导航、选择、保存、奖励或震动。
- 悬浮或键盘聚焦喇叭显示操作名称、cue 标识和实际 WAV 路径；按钮及保存／收集／完成均显示 `ui-sounds/soft-garden-v1/` 下的文件，材质音注明“程序合成音效”及 `soft-audio.ts`。悬浮不自动播放，提示可移入阅读；Esc 先收起提示，不关闭其所在弹窗。提示随目标定位并避开视口边缘。
- 可收起面板保留滤镜与数量，方便窄屏检查。再次展开后关闭滤镜会移除角标、轮廓、监听器与动画帧，并停止尚在播放的试听。
- 开关显示当前操作对应的开／关音；重复当前选项、禁用项和关闭总声音的动作不标注。保存与复制角标表示实际成功时的反馈，试听不会伪造成功回执。
- 试听复用实际 UI／结果 WAV 和共享材质音生成器，遵守现有总音效开关、后台与失焦停播。未就绪时提示再点，不在解码完成后自动补播。正常业务声音会停止试听后接管。
- 范围为共享 App 界面和心愿架小物；Three.js 画布内部动作、独立分享落地页和原生故障恢复不在此滤镜中。角标数量是当前可见的已标注目标数，不是所有按钮的覆盖率。

## 接入约定

界面操作在处理函数旁使用 `data-audio-cue` 声明对应 `UiSound | SoftSound`。有条件的操作用同一状态计算下一次操作的声音，无效时不设值。不要只因为是按钮就添加声明，也不要给本来无声的操作增加声音。新的复合组件须明确向实际目标转发 `soundCue`。

`apps/cyber-bless/src/AudioDebugConsole.tsx` 仅由 Web `import.meta.env.DEV` 懒加载，经 `BlessingApp.debugOverlay` 放入稳定的 App 上下文。开发 UI 使用 `audioInspector.prepare/play/stop`，不调用控件处理函数；原始界面事件链不读取这些标注。角标通过同一弹窗内的兄弟 portal 绘制，不嵌套 button/label，不占业务布局；扫描考虑滚动、剪裁、DOM 变化和入场动画结束。

本次纯产品调试层变更已按 [文化关联规范](scene-provenance.md) 判断影响；沿用 [界面音效盘点](research/2026-11-03-ui-operations-audio-audit.md) 的产品反馈归属，不改变文化主张、场景动作、标题、来源绑定或存档 ID。
