# 柔和树影与圆润叶簇

日期：2026-11-05。用户反馈近景树影太硬，叶子不够圆润。继续仅调试预览，不改变正式默认和文化主题树。

## 原因与处理

已读本地固定来源 `foliage.js` 的 `bakeCards` 和 `glb.js`：叶卡每个顶点保留朝外簇法线，与卡片三角形朝向独立。已读项目锁定的 Three r170 `normal_fragment_begin`：普通双面材质会在背面再次翻转法线。真实 WebGL 对照中，同一朝外法线的卡片仅翻转三角形顺序，原普通材质中心像素最大通道差为139，印证了异常明暗碎块的原因。

`tree-foliage.ts` 仅为 Simple Tree 来源的叶材质保留两面一致的簇法线，将烘焙顶点色反差系数降为0.68；普通 PBR／Lambert 光照使用低峰值包裹漫反射，让亮暗过渡更柔和。墨线等分段风格保留自身光照。`toon-surfaces.ts` 为适配材质重建相同处理，避免 clone 后丢失编译回调。源 GLB、几何、法线、叶片遮罩及配色数据均不改。没有额外渲染通道、贴图或第三方依赖。

替代树实际可见时，共享主光使用支持 radius 的 PCF 过滤，半径12、投影强度为进入预览前的52%。保存每盏主光原强度和过滤半径，在原景准备、正式截图和卸载时恢复。夜景灯火位置、动画和光强不改；近景布局与中央留白也不改。

试用 alpha-to-coverage 后发现当前画面会出现白边，已撤下；沿用原透明裁剪，不以半透明白边冒充柔和轮廓。图片对照保存于 `artifacts/tree-softness/`，实景截图在 `artifacts/tree-framing/`。

## 叶片发白回归修正

同日用户在新增椿树预览中指出白块。此前的正反面一致性与 shader 编译检查没有覆盖亮度异常，旧实景图中的白色斑块也未被正确拦下。实际在 `alphaToCoverage=false`、透明裁剪正常、纯蓝不透明背景下仍可稳定复现，不能把这次白块归因于透明边缘。

本地 Three r170 的 `lights_physical_pars_fragment`（`V_GGX_SmithCorrelated`、`BRDF_GGX` 及 `RE_Direct_Physical`）显示：GGX 可见性项使用真实的法线／光线、法线／视线夹角；朝外簇法线可使两项均为零。旧柔光实现替换公共 `dotNL`，将非零的包裹光同时送入漫反射和镜面反射，后者在背光／背向视点处被极大放大。600×600 的同一椿树固定对照中，旧 original 有3,884个近白像素，旧 toon-soft 有4,012个；仅恢复镜面反射的真实入射量，两者白块即消失。没有缺失纹理或运行时外部资源请求。

修复仅让包裹光进入 PBR 漫反射；镜面反射继续使用真实入射量。保留原有簇法线、叶色、AO、柔和漫反射和 Lambert 处理，并更新 shader 缓存键。未修改 GLB、树种推荐、默认设置、文化主张、来源卡、目录、metadata 或存档，沿用上文来源边界核查。

新增 `node scripts/verify-tree-foliage.mjs`，先在旧实现中得到预期失败（椿树 round／original 的3,884个近白像素），再在修复后通过：8种 Simple Tree 树形×2种变体×original／toon-soft，共32组真实 WebGL 图像中近白像素均为0，树木可见、背景不透明、无 shader 回退及页面错误。结果与图片保存于 `artifacts/tree-foliage/`；此检查补充此前仅验证法线一致和编译成功的检查。
