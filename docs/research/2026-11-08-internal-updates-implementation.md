## 发现并修复的关键问题

- Expo CLI 57.0.32 把 DOM 分块改名为 MD5 后留下旧依赖引用，实际导出报缺少 `__common` 文件。仓库中的受限 Metro 包装仅让生产 DOM MD5 导出生成完整单文件 JS，普通网页分块保持原行为；使用实际安装的 serializer/exporter 验证先失败后通过。代价是 DOM JS 约 12 MB，场景代码一起加载。
- SDK 57 原生只允许覆盖构建时声明过的请求头。配置预留空 `X-Feedback-Token` 键，运行时再读取本机已存邀请码；安装包不包含真实邀请码。
- 仍运行嵌入 A、已缓存 B 时，回到嵌入版必须发送签名回退指令，不能因当前已是 A 返回 204；真实下载/HTTP 回归验证回退时间晚于 B。
- Android 图片编译可能改变 PNG 字节，且 hashless `Asset.fromURI` 会误用同名旧缓存。字节不变的二进制别名、显式 MD5 Asset 实例和实际 Expo Asset 回归覆盖这两点。
- 准备流程自行重建忽略目录中的 public/别名，并在导出前后对照已跟踪源码和实际导出字节，拒绝陈旧或瞬时篡改的生成输入。
- 正式更新默认关闭；原生接入通过冻结布尔输入控制，并绑定源码、准备、构建、验证和交付回执。签名配置验证使用私下捕获的完整 evaluated config，不能使用会剥除签名字段的 public config。
- 密钥配置在任何写入前解析真实父目录并检查全部 Git 工作树，包括目录联接；私钥保留在外部配置目录。
- Expo 原生错误恢复不覆盖所有 DOM 错误。补充独立原生修复面板、渲染边界和前台 30 秒就绪检测，失败后先卸载 DOM，再显式检查/下载/应用在线修复。等待存档、反馈和 Widget 写入；覆盖嵌入回退、保存屏障、错误恢复、进度、边界和超时测试。损坏 DOM 的离线自动回退没有保证。
- Windows CRLF 与配置加载器的路径排除差异会造成错误 runtime。指纹使用字节级文本换行规范化，保持二进制原样，并严格补齐安装 SDK 的配置工具 JS 排除范围；将冻结 Pod 锁和原生 Widget 文案输入纳入指纹。公钥 PEM 写入和 Git 检出统一 LF，证书信任身份不变。
