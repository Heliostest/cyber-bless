# 反馈后台自启动与恢复

用户要求后台自动启动、持续运行，并在公网地址变化时自动输出。沿用现有 Node 接收服务、Quick Tunnel、邀请码与收件目录；本轮按当前 Windows 用户登录后启动实现。

采用 Windows 当前用户计划任务和 Node 守护进程：计划任务登录及每分钟检查启动，忽略重复实例；隐藏运行，不依赖 Codex 或开发服务器。守护进程分别管理接收服务与隧道，退出或连续健康检查失败后退避重试。Windows runner 用 Job Object 清理进程树；CLI 的 IPC 断连也主动清理子进程。暂停任务后停止，防止自动拉起抵消手动停止。

与增加 PM2/Windows 服务相比，此方案沿用现有 Node 与 PowerShell，无新依赖或管理员服务账户。两个手动终端无法提供登录启动和异常恢复，因此保留作诊断入口。

实施与验证：
1. 先增加子进程退出、健康超时、停止清理、重复实例、URL 变化与日志回归测试。
2. 增加 supervisor、受限本地单实例锁、原子状态文件、滚动日志，CLI 支持 IPC 生命周期。
3. 增加 Windows 登录任务、进程树 runner，以及 install/start/stop/status/uninstall/logs 命令；更新文档和 npm 脚本。
4. 运行后台 Node 测试、PowerShell 解析检查，安装并实测接收服务/隧道退出恢复和公网健康。保留原数据，不提交邀请码、地址或日志。

边界：电脑关机、休眠、未登录或网络/Cloudflare 故障期间不能保证在线；恢复后继续重试。Quick Tunnel 地址变化仍须分发给测试者，不创建固定域名或发布新 App。
