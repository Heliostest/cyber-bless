# 心愿页减法与仪式入口设计

日期：2026-10-27。状态：交互方向已确认；用户否定首轮扁平视觉，要求恢复 Animal Island UI 后重做，当前以本修订为准。

## 用户意图与已确认选择

当前心愿页装饰过多，通用心愿灯只是参考图片；直接填表保存却使用“点亮心愿灯”的动作名称。用户确认先亲手完成小仪式，再记下心愿，并选择“简洁列表＋已有互动场景”。

目标是让心愿成为视觉主体，让记录发生在实际互动完成之后。完成仪式后记录仍可跳过，不强迫用户填写。首页只保留一个通用开始按钮；用户追加的已获小物展示也可直接进入对应互动。

## 考虑的方案

- **简洁列表＋已有互动场景（用户选择）：** 去掉通用灯包装，沿用现有场景动作及完成后的可选记录。优点是流程与真实功能一致，可保留各场景自己的心意与来源；代价是新增入口需要先选一个互动。
- **以可操作的灯为中心：** 将灯变成专属互动主角。视觉更集中，但会改变当前隐藏灯景的产品策略，并让不同来源的心愿统一套上灯的意象。本次不采用。

## 首页

首页结构：原有飘带标题“我的心愿” → 已获祈愿小物悬挂架（有收藏时） → 胶囊筛选（进行中／已如愿／先放下） → 沙色心愿卡片 → 唯一通用糖果主按钮“去许愿”。

删除顶部加号、宣传横幅、灯缩略图、“心愿灯”筛选名和重复的点亮文案。列表每条只呈现心愿正文、原有只读状态标签、日期及已有记录数量；保留沙色底、软白边、圆角和台阶，靠删减重复内容改善层级。空状态不再重复放一个创建按钮。

视觉必须沿用 [Animal Island 正式 UI](../../design/island-shell.md)：薄荷波点底 `--dots` / `--island #cdf1e6`、暖棕文字 `--ink #4a2a12`、沙色 HUD 面板 `--sand #fbf3dc`、软白边、糖果渐变按钮、按压台阶、燕尾飘带、圆体与原有字重、四色浮动底栏。不得重定义全局或页面 token，不得通过 wishes 专属规则替换标题、背景、字体、导航、按钮或卡片的视觉语言。首轮扁平薄荷绿样式已撤回。

## 完成仪式后再记录的路径

`心愿 → 去许愿 → 选择小仪式 → 完成实际动作 → 可选记录 → 心愿列表`

旧 `new` 路由改为仪式选择页，删除可直接创建心愿的表单。保留技术路由以兼容已有导航。选择器采用双列小物卡片，沿用已有沙色面板、场景徽章、白边与台阶；直接入口只显示小物图标与场景名，心意说明仍在实际场景内呈现，避免选择页重复堆叠文案。

选择页优先显示需要继续处理的旧小物草稿和已收下、可使用且允许完成后记录心愿的许愿小物，保留现有消耗与草稿语义。无写愿能力的旧小物继续保留在存档及其他适用用途；已有待处理草稿不受新增筛选影响。同时提供当前可见、`kind: wish` 且 `optionalWish: true` 的现有场景作为直接开始的选择；相同场景有可用小物时优先使用小物，不重复显示。没有小物的新用户也可当场完成并记愿，不依赖“今日”恰好推荐许愿场景，不增加每日次数或解锁门槛。

入口沿用 `useOpenScene`；新开始需走完整互动，未完成的普通访问可按现有检查点继续。记录只复用宿主已有的完成后写愿控件，不提前显示输入框、不新增第二套保存机制。隐藏场景不重新开放，不将感谢、礼敬或自省场景统一改称许愿。

## 已获得祈愿仪式的悬挂展示（用户追加）

心愿页在标题下展示已经收下的祈愿小物，使用小木架、吊绳与真实场景图标，延续原来的悬挂小物意象和 Animal Island 皮肤。每个 collectible.id 独立保留，同场景不同天收下的小物不合并状态。

未使用的小物保持明亮糖果色并标“未用”，已使用的降低图标饱和度并标“已用”，文字保持可读。有待处理草稿的标“接着刚才”并先显示，其次未用，再次已用；同状态按现有收藏的新近顺序。默认只展示前三件，多于三件时可展开全部，未获得小物时不占空展架。

点未用且允许记录的已支持场景，进入对应 vessel 的实际互动；打开时不消耗、不创建心愿。待处理文字继续走原 vessel 选择，不重置或清草稿；已用、无写愿能力或引擎不支持的收藏进入原收藏详情。隐藏场景、普通祈福收藏、纪念章与没有消耗语义的旧版收藏不伪装成可用祈愿小物。木架仅是产品收藏展示，不宣称任何传统悬挂做法。

## 详情与后续操作

删除详情和还愿页中的通用灯插画。心愿正文为主体；有 `sourceSceneId` 时显示实际场景名称，无来源的旧心愿按原记录自然展示，不补造来源。

保留状态、日期、历史约定、努力记录、归档、确认实现与还愿能力。暂无记录时用一行空状态；记录与还愿说明降低视觉权重。每个状态仍只有一个主要下一步。不在许愿前要求选择分类和还愿方式，旧存档字段继续保留，由现有默认值及还愿页处理。

## 来源与兼容边界

已读 `AGENTS.md` 与 `docs/scene-provenance.md`。本次只改变宿主入口、布局和记录表述，不修改任何场景器物、动作、完成条件、来源身份、介绍或传统事实。沿用 `docs/research/2026-10-19-ritual-intentions.md`、`docs/research/2026-10-19-ritual-wish-flow.md` 的既有核查范围；在新的宿主改版研究记录中说明文化影响与不适用项。无需为通用装饰灯建立来源卡，也不借用隐藏灯景。

保留 wish ID、sourceSceneId、状态机、notes、category、returnMethod、小物消耗记录、待处理草稿、到达动画目标及存档版本。core 的通用 wish.create 继续服务场景记录及兼容；本次移除的是面向用户的直接填表入口。

## 验证与交付

- 检查首页只有一个新增入口，无宣传灯图，三个筛选与旧心愿仍可用。
- 检查旧 new 路由无直接保存表单；无小物也能选可见且允许写愿的互动；旧小物消耗和待处理草稿继续可用，隐藏/不允许写愿的场景不会混入。
- 沿用并运行“未完成无写愿、完成后主动保存、取消不创建、重复提交不重复保存”相关回归；检查来源名称与旧无来源心愿。
- 运行受影响 App 测试与生产构建；使用真实浏览器检查 320px、390px 和桌面布局、交互、无横向溢出及可见焦点，明确核对 Animal Island 背景、飘带、渐变、面板与底栏，保存改版截图。
- 独立复核实现是否符合本设计；事实与文化影响审阅单独记录，不以技术测试代替。

实现细节由执行者决定：局部样式选择器、组件拆分、场景列表的稳定顺序与适量间距。交付是本地可运行修改与验证，不包含商店素材更新或发布。
