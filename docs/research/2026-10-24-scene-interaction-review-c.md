# 2026-10-24 场景交互审阅 C 组

按 `artifacts/scene-interaction-2026-10-24-batches.json` 的 C 组顺序，分五批逐项审阅 51 个 `scene.ts` 场景。核查对象为实际实现、相关模型/几何、输入验收和场景 README；不是依旧策划推导传统流程。本记录与各场景 README 互链。

## 范围与判据

用户要求允许多于三步，以真实器物与有据实践为准；可反复演奏的场景达到最低体验量后继续交互，直到主动结束；手机输入应按看得见的目标、手势意图与松手位置验收。

本组保留了有独立意义的取物、组装、安放、静看阶段。纸鹤实际包含多次折叠，花环实际包含四簇串花，均未被压成三个单次点击。没有为了增加数量而凭空补出传统礼序。佛光山浴佛的三杓对应既有机构证据，继续保留三杓；木鷽交换、节分撒豆、敬老浇水等不扩大成无限累积仪式。

触屏共同问题为很细的弦、绳、木柄和花枝必须精确命中单个网格，以及浏览器合并移动事件后，合理的按下→松手位移被当作“没有移动”。本组将遗漏场景接入共享 `createTouchTarget` 的有限 CSS 像素容错；仍使用可见真实几何、检查前景遮挡并拒绝画布外输入。共享 `createObjectPointer` 的松手补采样和 `completesDirectionalDrag` 容错由主代理维护。本组更新旧拒绝断言，保留孤立松手、错误方向、过短、退回、多指和取消的拒绝测试。

下表“保留”不等于未检查；它表示现有阶段能表达这一片段，增加步骤或无限重复会改变当前体验范围。来源归属、技术 ID、引擎版本与完成存档 3 均保持。

## 连续乐器的产品协议

三个连续场景达到最低三次后保持物件输入和辅助按钮，新增独立「结束仪式」按钮。第一次与第二次提交进度 1，第三次及后续提交 2；只有显式结束提交 3 并派发一次完成事件。进度 2 恢复即有结束资格，旧进度 3 静默完成。旧进度 2 原来可能只做两次动作，这一特例按存档兼容处理；不将其倒写为传统次数。

取消、失焦、暂停、多指、动画未落定、宿主回调重入均不能绕过输入归属或自动结束。琴弦回振、鼓槌落下和木珠绕行仍保留。合成反馈音不是实录或传统曲目。波德兰第三交互从转框改为再拍，后续左右交替；转框属于主动结束姿态。拨浪鼓回正与下一轮高度衔接，结束才收低。
