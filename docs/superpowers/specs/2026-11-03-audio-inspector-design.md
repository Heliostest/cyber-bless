# 界面音效覆盖滤镜

用户要求在调试台开启滤镜后，给有声音的按钮或区域右上角加可试听的喇叭按钮；用户选择新增仅 Web 开发环境可见的入口。

使用现有 React App 实例，在开发宿主注入调试台。默认关闭，开启后标出当前可见、可操作、已接入声音的界面控件和心愿架小物。状态开关标注下一次有效操作的声音，提交标注成功后的声音；重复选中项、禁用项和原本无声的操作不冒充有声。Three.js 场景动作继续由各引擎管理，本滤镜名称和说明明确为界面音效，不据此推断画布内所有动作的覆盖率。

方案：选择与真实处理函数相邻的声明式音效标注，由开发浮层读取；比根据按钮文案/CSS 猜测可靠，也无需先执行一次业务操作才能发现。浮层不嵌套 button、不占布局，跟随滚动/动画/弹窗，鼠标、触摸与键盘均可试听。试听复用 App 现有音频服务，只播放声音，无振动、导航、保存和奖励。遵守总声音开关、失焦/后台停播；未就绪提示再试，不迟到补播。

控制台可收起成显示数量的小按钮，保留滤镜，便于窄屏检查；关闭滤镜或卸载控制台时移除角标和观察任务。生产 Web 与原生入口不加载控制台。功能开关不进入用户存档，不恢复旧 Shader 覆盖。
