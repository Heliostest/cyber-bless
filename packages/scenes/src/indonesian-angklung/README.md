# 竹音轻摇

以印度尼西亚公开竹乐器 Angklung 为背景的原创当代欣赏练习。竹架、两根不同长度的空腔竹管、上部开槽、竹节、藤绑及下横轨均由程序生成。`indonesian-angklung` 是独立公开工艺卡，C / 低是产品设计分级。此场景不归入 Sunda Wiwitan 信仰卡，不展示宗教仪式，不声称教授完整制琴、调音或演奏技艺，也不保存心愿。

主体直接置于宿主的阳光廊台环境，不使用小桌或倾斜展示板。竹管有实际厚壁空腔和朝前开槽，上部保留后侧竹舌；下部竹脚落在横轨之间的承托面，绕竹脚中心轻摆。四根藤绑的一端连接横梁表面，另一端连接竹管上部表面，拖动和回稳时复用顶点与法线缓冲更新曲线，不创建新的 GPU 几何。

## 动作与恢复

1. 拿住上方浅色横柄，向屏幕左方短拖。
2. 拿住同一横柄，向右短拖，完成一次往返。
3. 原位轻点长竹管正面，静听后结束。

两次摇动分别要求有方向、实际移动过的短拖。竹架横向移动 0.2 场景单位；两根竹管以不同幅度滞后轻摆，接受输入后经过 0.78 秒回稳才报告进度。减少动态直接进入同一最终姿态。检查点 0 为居中，1 为左移，2、3 回到居中；所有检查点的竹管均静止。普通访问和返回访问恢复 0–3 均不会报告新进度、播放声音或触发振动。

本物体使用同一个原创轻柔合成音：392 Hz 基频与低音量的 784 Hz 八度泛音，持续 0.19 秒、峰值增益 0.005。它只在接受的操作后播放，并读取宿主音效开关；没有复制录音、传统曲目或形成旋律。声音是缩略欣赏反馈，不模拟真实竹管共振及准确调音。

## 真实表面与自动化锚点

| 检查点 | 网格名称 | 局部表面锚点 | 屏幕动作 |
| --- | --- | --- | --- |
| 0 | `angklung-frame-grip` | `[0, 0, 0.10]` | `[-60, 0]` px |
| 1 | `angklung-frame-grip` | `[0, 0, 0.10]` | `[60, 0]` px |
| 2 | `angklung-tube-long-body` | `[0, 0.7, 0.19]` | 原位轻点 |

锚点经网格的 `localToWorld` 后投影。起点必须首先命中对应的真实不透明表面，无隐形命中板。前两步沿指定方向位移为 42–84 px，全程最长位移不超过 90 px，纵向偏离不超过 18 px，逆行不超过 8 px，回拉不超过 9 px。最后一步要求全程与结束移动距离均小于 12 px，并再次首先命中长竹管。错误表面、只有松手位移、短距离、反向、横向、多指、取消和捕获丢失均不会完成。

原生辅助按钮最小 44×44 px，Enter / Space 完成相同步骤。过渡期间禁用物体与按钮输入。每个暂停、失焦和销毁边界都使准备中的输入失效；宿主同步反馈回调内派发的事件不能污染指针所有权或跳过步骤。回调内短暂暂停再恢复也会阻断后续声音和完成事件。

稳定组名为 `angklung-world`、`angklung-subject`、`angklung-frame`、`angklung-tube-long`、`angklung-tube-short`。藤绑网格为 `angklung-lashing-{long|short}-{front|back}`；两端节点分别为 `angklung-suspension-{long|short}-frame-{front|back}` 与 `angklung-suspension-{long|short}-tube-{front|back}`。竹脚与承托中心为 `angklung-foot-{long|short}` 与 `angklung-socket-{long|short}`。

## 来源与边界

[UNESCO：Indonesian Angklung](https://ich.unesco.org/en/RL/indonesian-angklung-00393) 提供广义事实：竹管由藤绑悬挂在竹架上，摇动或轻击竹架发声，每件乐器通常产生一个音或和弦。场景只借用这些公开概述，其结构比例、几何和声音均为原创缩略表达；未使用来源图片、视频或音频。

## 验证

`npm run test -w @wbr/scenes -- src/indonesian-angklung/scene.test.ts`

49 项 focused tests 保留真实 Three.js 几何、射线、提示和指针控制，只替换 GPU 与音频硬件边界。覆盖两次独立摇动、键盘渐进回稳、相同最终姿态、音效开关和固定基频、空腔与开槽、藤绑端点和竹脚接触、缓冲复用、首个不透明命中、284×390 / 350×408 / 1280×600 全主体顶点、静默恢复与返回、无效手势（含松手坐标中的末段回拉）、生命周期与同步重入，以及资源恰好释放一次。

红绿过程与自查见 `artifacts/ebru-angklung-pair/angklung-verification.md`。完整测试、应用构建、浏览器鼠标／原生触屏／键盘、移动导出和最终画廊由根任务统一验证。
